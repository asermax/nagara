# Cassettes over mocks

The pipeline suite replays the services behind its HTTP boundaries, Firecrawl and Gemini through the AI Gateway, from vcrpy-shaped cassettes, so the clients' real request building and parsing run against the recorded shapes. The replay library is `replayCassettes` in `common/testing/`, which turns cassettes into msw handlers; `docs/technical-design/common-package.md`, "Replaying cassettes in tests", describes it. Stand-ins replace the boundaries that are not plain HTTP, such as the Flue agents.

- Replay a recording when one exists. The library matches a request on its method, scheme, host, port, query, path and JSON body, with every `itm_` id normalized on both sides so one cassette replays across any minted id. Headers take no part in the match. Repeated identical requests replay in recorded order, which is how a sequence of polls or a retry after a 429 replays. The library rewrites a gateway URL to the recorded provider host before it matches the request.
- Fabricate a cassette when the request cannot be recorded ahead of the run. A fabricated cassette is request and response pairs hand-built from the boundary contract, and the suite writes them as JSON, which the YAML parser reads. The suite fabricates the Firecrawl pages for the test articles this way. The trade is that a recorded cassette is evidence the service answered, and a fabricated one is the contract restated as a fixture, so a change in what the service really returns goes unnoticed.
- A handler built on the contract replaces a cassette when the request is not known before the run, or when the test has to read what was sent: Modal's start and result endpoints (the test asserts the start body and headers), image downloads, and image describe requests, which carry bytes that the Images binding produces at run time. The handler goes in front of the cassettes' catch-all handler.
- The catch-all throws on an unmatched request, and msw answers the request with a 500 instead of rejecting the fetch. A step that recovers from a 500 (a describe child falling back to the floor) hides the miss, so a test asserts the outcome it expects (the spoken form, the stored keys, the request count), not only that the item reached `ready`.
- A refused connection records no interaction, so the unreachable case cannot be a cassette. Point the client at a closed port on 127.0.0.1, which refuses the connection at once.
- The Flue agents are not HTTP the suite can intercept, since the vitest pool never builds their Durable Objects. A plugin in `pipeline/vitest.config.ts` resolves the agent conversation module to a test stand-in that answers with the reply that the test scripts, so the stand-in never reaches the production bundle.
