# Your spike: `cross-script-binding`

Spike folder: `/home/agus/workspace/asermax/nagara/.scratch/cloudflare-migration/spikes/cross-script-binding/`

**Question:** can an API Worker (separate deployable) start and read a Workflow defined in the pipeline Worker through a cross-script Workflow binding (`script_name`), deployed and in local dev, and what happens depending on which of the two deploys first?

Build a minimal pair: `nagara-spike-xs-pipeline` (defines a small Workflow, `nagara-spike-xs-item`, with a couple of steps and a sleep) and `nagara-spike-xs-api` (binds it with `script_name`, `POST` creates an instance with a chosen id, `GET` reads its status). Deploy both and exercise it. Then: deploy the API first with the pipeline absent (delete or rename to test), deploy the pipeline first, redeploy the pipeline with a changed Workflow while instances are running and sleeping, and see what `create()` with a duplicate id and `createBatch()` do from the other script. Also run the pair in local dev (one `wrangler dev` with multiple `-c` configs or separate processes) and report whether the binding resolves locally. A separate spike (`local-dev`) covers the whole local setup with D1/R2; you only need the binding.
