# Context

nagara (repo `/home/agus/workspace/asermax/nagara`) is evaluating a move of its API off Railway/Python onto Cloudflare. Read the repo's `CLAUDE.md` first; read code and docs freely, but **edit nothing tracked in the repo**: no branches, no worktrees, no commits, no pushes, no Linear.

The design under test ("TypeScript API + item Workflow", drawing at `.scratch/cloudflare-migration/canvas/cloudflare-options.tldr.json`, shapes prefixed `ts-`):
- The API (`api/`, today Python FastAPI on Railway) becomes a TypeScript Worker: X-API-Key auth, POST /items (insert row in D1, start the item Workflow), GET /items/{id} (read D1), GET audio/images (307 to a presigned R2 URL), POST /items/{id}/retry. A separate deployable from `pipeline/`.
- D1 replaces Postgres (hand-written SQL migrations applied with wrangler). R2 replaces the Railway bucket.
- One flattened item Workflow in `pipeline/` does all work per item: 1 fetch the page (Firecrawl), 2 wait for the domain's lease (DomainQueue DO, global), 3 run the recipe in the Dynamic Worker sandbox (Flue agents author/revise it, new recipe version written to D1), 4 images: fetch, SVG→PNG, re-encode WebP, store in R2, 5 describe images (Gemini through AI Gateway), 6 spawn TTS on Modal over HTTP, 7 sleep and poll TTS until done, 8 store audio in R2 and write units/timing/cost/ready to D1. Each step writes item status to D1.
- `tts/` stays Python on Modal and gains two web endpoints: start synthesis (returns call id) and fetch the result by call id.

Today's pipeline: `pipeline/wrangler.jsonc`, `src/app.ts`, `src/queue/domain-queue.ts`, `src/queue/job-index.ts`, `src/workflow/extraction.ts`, `src/runtime/run.ts`, `src/agents/`, `src/workflow/world.ts` (WORLD_SEAM). Tests: vitest 4.1 + `@cloudflare/vitest-plugin` in workerd. Today's API: `api/app/` (`endpoints/items.py`, `service/pipeline/steps.py`, `service/images.py`, `service/describe.py`, `service/tts.py`, `service/storage/`), cassettes under `api/tests/cassettes/`.

Facts already researched from docs (not tried): Workflow step result ≤ 1 MiB (JS steps may return a ReadableStream exempt from it); 10,000 steps per instance default (up to 25,000); CPU 30 s per step default (up to 5 min); sleeps don't count as steps; cross-script Workflow binding via `script_name`; `create()` throws if the id exists, `createBatch()` is idempotent. Workers: 128 MB memory per isolate, `waitUntil` 30 s. R2: S3 API region `auto`, presigned URLs 1 s–7 days on `*.r2.cloudflarestorage.com`. D1: SQLite, `run()` returns `meta.changes`, migrations tracked in `d1_migrations`, `--local`/`--remote`, no down-migrations. Modal has no public REST spawn/poll API; the documented pattern is your own web endpoints (`POST /submit` → `fn.spawn.aio`, `GET /result/{call_id}` → `FunctionCall.from_id(id).get.aio(timeout=0)`, 202 while running), protectable with proxy auth tokens; results expire after 7 days.
