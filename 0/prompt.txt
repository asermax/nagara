# Implement: markdown and lists, pipeline/

## The change
Read first: /home/agus/workspace/asermax/nagara/docs/technical-design/markdown-units.md, recipes.md, extraction-service.md (on this branch), and the settled design + program architecture at /home/agus/workspace/asermax/nagara/.scratch/markdown-and-lists/design.md.
Summary: every recipe's `toMarkdown(element)` serializes the element WITH its own tag (today it uses cheerio `.html()`, the inner HTML, which drops the h2/blockquote/ol/table tag), wraps the content of a `<pre>` without a `<code>` child in `<code>`, and runs Turndown with the fixed config plus `@truto/turndown-plugin-gfm` (add it next to turndown 7.2.4; it reaches the sandbox through scripts/build-injection-bundle.mjs). In the SAME sandbox call, after the recipe returns, the runtime splits every declared paragraph unit whose element is an <ol>/<ul> holding a <pre>, <img>, <figure>, <picture> or <svg> at any depth into list part / code or image unit / list part in document order (each list part a clone in its own <ol>/<ul>, converted with the same converter; the part after continues start on ordered levels and opens with an empty <li> at each enclosing level so resumed items keep depth; an item whose only content was the block is not repeated; image unit src/alt read as the element carries them), then prepends a paragraph unit '# <title>' when the extracted title is not empty. The sandbox reply carries the title, the declared units (with paths, as today) and the flattened units. The host validates the DECLARED units exactly as today plus a new check: a declared unit whose own element is an <li> is a problem whose line names the unit (position and path), the list it belongs to, and the rule that a recipe hands a list over whole. Clean -> runRecipe returns the flattened units (the workflow and the agent extract tool both get them); problems -> the report, flattened discarded. The shared RECIPE_CONTRACT (pipeline/src/agents/prompts.ts, embedded by both author and revision instructions) gains these plain rules: markdown is GFM and the whole element goes to toMarkdown; a list is one unit even when it holds code or images; the runtime may split a unit into several and the extract tool shows the split result; a formula is its alttext as plain text with no delimiter; attributions (blockquote footer/cite), <dl>, footnotes, heading self-links and any heading repeating the title are left out through the recipe's includes and ignores; task-list checkboxes are kept.
Out of scope: api/, tts/, the four stored recipes (ASE-70), lazy-load src resolution for split images, figure captions, a split that throws, empty list parts.
Reference only (never copy wholesale; build it clean): the spike's split at /home/agus/workspace/asermax/nagara/.scratch/markdown-and-lists/spikes/markdown-fidelity/runner/split.mjs and its findings-round-5.md (it hit a bug: a whitespace-only text node left after pulling a nested list out of an item became a spurious empty <li>).
