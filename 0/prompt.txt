# Your spike: `local-audio-upload`

Question: can the production Modal TTS app upload a finished audio file into the R2 that local development simulates on disk, using the same mechanism as production (Modal receives a destination URL with each synthesis request and PUTs the audio there)?

Design facts: in production the API/pipeline hand Modal a presigned R2 PUT URL. Locally the pipeline runs under `vite dev` (Cloudflare Vite plugin) and the API under `wrangler dev`, sharing one `--persist-to` state folder. A researcher found an experimental, undocumented wrangler option (workers-sdk PR #14280, merged 2026-07-27): `local_dev.experimental_s3_credentials` (`accessKeyId`, `secretAccessKey`) on an `r2_buckets` entry serves the local bucket over the S3 API at `/cdn-cgi/local/r2/s3/<bucket-id>` on the dev server, with SigV4 checked for headers and presigned query parameters. Unknown: which wrangler version ships it, whether the Vite plugin's dev server exposes it, whether a presigned URL signed for a tunnel's hostname is accepted, and tunnel limits for a ~12 MB PUT.

Variants to race (same input, same measure):
- A: local S3 endpoint. Enable the option on a minimal Worker under `wrangler dev` (latest wrangler) and, separately, under `vite dev` with the Cloudflare Vite plugin. Presign a PUT URL (aws4fetch) whose host is the tunnel's public hostname, and upload.
- B: a local Worker route that accepts the PUT (authenticated with a token or a signed query string you choose) and writes it into local R2 through the binding.
For each variant, expose the dev server through ngrok (installed at /usr/bin/ngrok; cloudflared is not installed; ask via <subagent-ask> if ngrok needs an auth token or you want cloudflared installed). The uploader must be a real external client on the internet: deploy a tiny Modal function in a Modal app named `nagara-spike-upload` (never touch `nagara-tts`; `~/.modal.toml` is configured) that PUTs a 12 MB Opus file, e.g. a copy of /home/agus/workspace/asermax/nagara/.scratch/cloudflare-migration/spikes/item-workflow/results/r3-long.ogg uploaded with the function, to the URL it is given. Then confirm the object is readable from the local Worker through its R2 binding and that the bytes match (size and sha256).
Also record: whether the local API, sharing `--persist-to` with the pipeline, sees the object; upload time; any body size limit hit; whether the same presign code works unchanged against a real R2 bucket URL (you may skip the real-bucket check if it needs S3 credentials; ask first if you want them).
Cleanup: stop the Modal app `nagara-spike-upload` and its tunnels/processes (by PID). No Cloudflare resources should be needed.
