## Annotation 2 (lines 31–33)
Comment on: "- **Our endpoint deduplicates:** the start endpoint in `tts/` receives a key (the item id plus the retry number). It keeps a key-to-call-id map in a `modal.Dict` and returns the existing call when it sees the key again. Whether `modal.Dict` can insert only when the key is absent, in one atomic step, is unverified. Without that, two simultaneous requests could both start a synthesis. - **Accept the duplicate:** now that Modal writes to R2 itself with a key derived from the item, a second run overwrites the same object with the same audio. The only cost is the extra GPU run, about $0.008. - **Split the step:** one step mints the key and saves it, and a separate step sends it to Modal. That only shrinks the window unless Modal deduplicates by that key, which brings back the first option."
> at that point i think we're okay with the duplicate, it's a very narrow case
