  ## 3. Per-element-kind handling in extract.py
  
  Everything below happens inside `to_spoken` (extract.py:34-58), operating on one `service_unit.display` markdown string at a time — there is no per-kind dispatch in the type system, only pattern checks against the string.
  
  - **Fenced code blocks**: `_FENCE = re.compile(r"^[ ]{0,3}(```|~~~)")` (extract.py:6). If `_FENCE.match(unit)` (extract.py:38), return the literal placeholder `"Code sample."` (extract.py:39). Note: this only fires for a unit whose `type` arrived as `"code"` from the boundary (arriving `display` starts with a fence) — regular paragraph markdown wouldn't normally match a leading fence. This is later overwritten by the describer (see Q2 step 7) unless describe fails/floors.
  - **Tables**: `_TABLE_ROW = re.compile(r"^\s*\|.*\|\s*$")` (extract.py:7); checked against the first line of the unit (extract.py:41). Routed to `_table_to_spoken` (extract.py:86-111): parses rows via markdown-it, treats `rows[0]` as header, and for each data row builds `"Header: cell, Header: cell"`, rows joined with `". "` and a trailing `"."` (extract.py:102-111). Single-row (header-only) table falls back to `sanitize_spoken(" ".join(rows[0]))` (extract.py:100). The whole result runs through `sanitize_spoken`.
  - **Headings**: no dedicated unit kind or fence match, so it falls through to the generic markdown-it inline-token walk (extract.py:44-58): parsed as a block, its inline children's `text`/`code_inline` content is concatenated (heading marker `#` is block-level syntax, stripped by the parser, never reaches the inline children). Result sanitized. Separately, `_HEADING = re.compile(r"^\s*#{1,6}\s+")` (extract.py:8) is used only inside `is_cruft` (extract.py:26) to strip a heading marker before comparing against the title/emptiness — not part of `to_spoken` itself.
  - **Paragraphs**: same generic inline-token walk as headings (extract.py:44-58) — `text` and `code_inline` child content appended, `softbreak`/`hardbreak` become a single space (extract.py:53-54); non-inline tokens (block wrappers) skipped.
  - **Blockquotes**: no dedicated handling — markdown-it still emits an `inline` token for the quoted paragraph's content, so the generic walk picks up the text; the `>` marker is block syntax and is dropped by the parser like any other block wrapper. Not a special case anywhere in `extract.py`.
  - **Ordered lists, unordered lists, nested lists**: no dedicated list/list-item unit kind and no dedicated list branch in `to_spoken`. See detailed answer in Q3-lists below.
  - **Inline code**: handled inside the generic walk — `child.type in ("text", "code_inline")` (extract.py:51) both append `child.content` with no distinguishing wrapper; the surviving backtick artifacts (if any leak through, e.g. from a table cell's raw inline source) are cleaned by `sanitize_spoken`'s `` re.sub(r"\*\*|__|\*|`", " ", text) `` (extract.py:80).
  - **Images**: not handled by `to_spoken`/`extract.py` at all — a `ServiceImageUnit` is intercepted before reaching `to_spoken` (images.py:70-79) and given its own spoken form via `_image_spoken` (images.py:143-151): `f"Image: {alt}"` if alt is non-empty, else `"Image with no description."` — later possibly overwritten by the describer.
  - **Links**: generic walk only collects `text`/`code_inline`/softbreak tokens from the inline children (extract.py:50-54); a markdown-it `link_open`/`link_close`/`text` sequence yields only the anchor text as a `text` child — the URL (in `link_open`'s `attrs`) is never appended, so it's dropped implicitly by omission, not by an explicit strip rule.
  - **Emphasis/strong (bold/italic)**: `em_open`/`strong_open` etc. are not in the `("text", "code_inline")` allow-list so their marker tokens contribute nothing directly; the inner `text` child still gets walked and appended. For emphasis that fails CommonMark's flanking rule and is left as a literal `**`/`*`/`_` marker in the token stream (comment at extract.py:56-57), `sanitize_spoken`'s regex `re.sub(r"\*\*|__|\*|`", " ", text)` (extract.py:80) turns any leftover marker into a space.
  - **Formulas/math**: no dedicated handling anywhere in `extract.py` — not mentioned in the file, no regex or token-type reference. Falls through the generic walk like ordinary text (math delimiters like `$...$` aren't CommonMark syntax, so markdown-it treats them as literal text content, appended verbatim).
  - **Horizontal rules**: no dedicated handling. An `hr` token is a block-level token with no `inline` type, so the `if tok.type != "inline": continue` guard (extract.py:47-48) skips it — `to_spoken` on a unit that is only a horizontal rule returns `""` after sanitize. That empty result is caught downstream by `is_unspeakable` (extract.py:61-65, "no letter or digit") and the whole unit is dropped (images.py:82-85) — this is presumably the "section-break ornament" case named in the `is_unspeakable` docstring (extract.py:63).
  
  ### Lists specifically
  
  There is **no dedicated "list" or "list-item" unit kind**, and **no dedicated list branch in `to_spoken`**. A list (ordered, unordered, or nested) is just markdown text inside one `display` string, and it goes through the exact same generic inline-token walk as a paragraph:
  
  ```python
  # extract.py:44-58
  out: list[str] = []
  
  for tok in _md.parse(unit):
      if tok.type != "inline":
          continue
  
      for child in tok.children or []:
          if child.type in ("text", "code_inline"):
              out.append(child.content)
          elif child.type in ("softbreak", "hardbreak"):
              out.append(" ")
  
  return sanitize_spoken("".join(out))
  ```
  
  Consequences for a list specifically:
  - `bullet_list_open`/`ordered_list_open`/`list_item_open`/`list_item_close`/`bullet_list_close` etc. are all block tokens (`tok.type != "inline"`), so they're skipped at line 47-48 — the `-`/`*`/`+`/`1.` markers never reach the accumulated text because they're block syntax consumed by the parser, not because of an explicit strip regex on the marker itself (unlike headings, where `_HEADING` exists as a separate regex used only in `is_cruft`).
  - Each list item's paragraph content still produces its own `inline` token, so every item's text is appended to the same flat `out` list with **no separator inserted between items** other than whatever `softbreak`/`hardbreak` tokens the source markdown contains between them (mapped to a single space, extract.py:54). There is no comma, period, or explicit pause token inserted between list items.
  - Nesting is fully flattened: a nested list's items are just more inline tokens encountered during the same walk, in document order, indistinguishable from top-level items once flattened.
  - Ordered vs. unordered lists are treated identically — nothing in the code branches on `bullet_list_open` vs `ordered_list_open`; both are simply skipped as block tokens.
  - The separate `_LIST_ITEM = re.compile(r"^\s*([-*+]|\d+\.)\s+")` regex (extract.py:5) is **not used inside `to_spoken`** — it's used only in `is_cruft` (extract.py:26, `_LIST_ITEM.sub("", _HEADING.sub("", text))`) to strip a leading list marker before checking whether the item's core text echoes the title or is empty. It never runs on the list content that becomes the spoken form.
  
  So a list like:
  ```
  - First item
  - Second item
  ```
  becomes spoken text with the two items run together with only a space between them (from the `softbreak` between list-item paragraphs), no marker, no enumeration ("one, two"), no pause — effectively "First item Second item".
  
  ## 4. The "drop" rule
  
  Commit `4ebae16 fix(api): drop job units whose spoken form has nothing to say` and `ad7953e refactor(api): define the no-letter-or-digit check once` (`git log --oneline -- api/app/service/extract.py`).
  
  The check is exactly `is_unspeakable`:
  
  ```python
  # extract.py:61-65
  def is_unspeakable(spoken: str) -> bool:
      """True when a spoken form carries no letter or digit (a section-break ornament, bare
      punctuation, or nothing at all): the synthesizer produces no audio for it, so the unit
      it belongs to is dropped."""
      return not any(c.isalnum() for c in spoken)
  ```
  
  Yes — it is exactly the "no letter or digit" check (`not any(c.isalnum() for c in spoken)`).
  
  It is invoked at `images.py:82`:
  ```python
  spoken = to_spoken(service_unit.display)
  if is_unspeakable(spoken):
      # Dropped before it becomes a typed unit, so display and timing leave together
      # (invariant 2); an ornament is no content lost, so it records no degradation.
      continue
  ```
  — a paragraph/code unit whose computed spoken form has no alphanumeric character is skipped before ever being appended to `text_units`, so it never becomes a typed `Unit` and carries no timing window (satisfies invariant 2 in CLAUDE.md).
  
  The same `is_unspeakable` core is reused inside `is_cruft` (extract.py:22-31), which additionally treats a unit whose stripped core text case-insensitively equals the article title as cruft — but `is_cruft` is used for the image-alt "good alt" test (images.py:182), not for dropping text units from the main list.
  
  If every unit is dropped (or none survived to begin with), `enrich_declared_images` returns an empty `units` list, and `ExtractionResolveStep.run` raises `ExtractionError("extraction: no surviving units")` (steps.py:164-165), failing the item.
